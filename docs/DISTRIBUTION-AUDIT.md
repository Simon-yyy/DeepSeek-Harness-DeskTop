## 三、P0：阻断分发的问题（6 项，必须全部解决）

### 3.1 P0-1 修复模块未接线，main.js 仍为旧逻辑

- **问题**：8 个修复模块（端口获取、归属校验、就绪等待、PID 清扫、shim 同步、凭据存储、版本护栏、启动编排）是孤立文件，main.js 中的旧 spawn 逻辑原样运行。
- **影响**：分发出去的 = 未修复版本。单实例锁、webPreferences 加固、导航拦截、凭据迁移、退出清理——全部未生效。前面全部工作对最终用户为零。
- **解决方案**：改写 main.js，接线清单共 11 处——单实例锁、启动编排调用 `startBackend`、webPreferences 加固、`will-navigate`/`setWindowOpenHandler` 导航拦截、凭据迁移调用、退出清理、崩溃兜底 kill、spawn 错误弹窗、日志文件接入、后端优雅关停、fuses 打包钩子。改写前提：先取得 main.js 原文。

### 3.2 P0-2 后端分发方式未定义，spawn 失败打崩主进程

- **问题**（三个子问题叠加）：
  1. `runCommand = 'dsh'` 依赖 PATH——普通用户电脑上**没有 dsh**；
  2. spawn 的 `ENOENT` 是异步 `'error'` 事件，当前无监听 → 主进程未捕获异常 → 闪退，用户体验为"双击图标，白屏，消失"；
  3. 若 dsh 是 `.cmd` shim：spawn 拿到的是 `cmd.exe` 的 PID → 端口归属校验必然误判为劫持；且 Node ≥20.12 对 `.cmd` 直接抛 `EINVAL`。
- **解决方案**：
  1. 后端内核随安装包内置（打包配置 `extraResources`），生产环境用 `process.resourcesPath` 定位，彻底摆脱 PATH，spawn 的是 exe/node 本体，PID 错位与 EINVAL 同时消失；
  2. 启动前存在性预检（`fs.existsSync`），缺失 → 弹"安装损坏，请重新安装"对话框而非闪退；
  3. spawn 前置 try/catch + `'error'` 事件监听 → 转结构化异常 `DSH_BACKEND_SPAWN_FAILED` → main.js 弹窗。

### 3.3 P0-3 端口绑定地址未强制回环 ⚠️

- **问题**：`buildArgs` 只传 `--port` 未指定 host。若 dsh 默认绑 `0.0.0.0`：① 局域网内任何设备可直接访问用户本地后端（数据外泄、盗用其 API 配额）；② Windows 弹防火墙授权框，普通用户恐慌。
- **验证方法**（现场确认）：启动后执行 `netstat -ano | findstr :308`，看本地地址列是 `127.0.0.1:3080` 还是 `0.0.0.0:3080`。
- **解决方案**：确认 dsh CLI 后在 `buildArgs` 显式加回环绑定参数；若 dsh 不支持指定 host，需改 dsh 或加本地反代。探测层（双探测 0.0.0.0/127.0.0.1）已就绪，但绑定行为必须从源头钉死。

### 3.4 P0-4 进程生命周期：崩溃后后端残留 + 硬杀数据风险

- **问题**：Windows 上子进程默认**不随父进程死**。App 崩溃 → 后端变僵尸进程，占端口吃内存，重启 App 再叠一个，卸载后仍残留。且 `child.kill()` 在 Windows 是 `TerminateProcess` 硬杀，后端写文件途中被杀会损坏数据。
- **解决方案**（按优先级组合，前三项必做）：
  1. **优雅关停协议**：正常退出先调后端 `POST /shutdown`（带 token），3s 超时再 `kill()`，最后 `taskkill /T /F` 兜底（是否具备 shutdown 端点属 dsh 侧待确认项）；
  2. **崩溃兜底**：main.js 挂 `uncaughtException` / `unhandledRejection`，先 kill 子进程再退出；
  3. **pid-sweep 启动清扫**（已有）+ NSIS 卸载脚本 taskkill；
  4. **终极方案（可选）**：Windows Job Object（`KILL_ON_JOB_CLOSE`），父进程无论怎么死都带走子进程，需小 native addon，成本收益自行决策。

### 3.5 P0-5 未代码签名

- **问题**：无签名 exe 在 Win10/11 上触发 SmartScreen"Windows 已保护你的电脑"，绝大多数用户点"不运行"。**这是分发转化率第一杀手**，技术做得再好也过不去这一关。
- **解决方案**：
  - OV 证书（年费数百美元，SmartScreen 信誉需数周积累）或 EV 证书（硬件令牌，即刻通过）——按预算和上线时间决策；
  - 签名后**安装包内所有 exe/dll 全签**，不只是主程序；
  - 上线初期主动向 Microsoft 提交误报白名单（microsoft.com/wdsi/filesubmission）；
  - 注意证书采购有周期，应与开发并行启动，不要等到最后。

### 3.6 P0-6 打包内容治理 + 运行期写路径

- **问题**（两个独立缺陷）：
  1. 照当前工程目录直接打包，会把 `test/`、`.agents/`（内含内部工作流配置）、`apply-fixes.ps1`、`verify-fixes.js`、`.bak` 备份全部塞进安装包——体积、信息泄露、AV 误报三输；
  2. 默认安装到 Program Files，**普通用户对安装目录只读**——任何运行期写安装目录的操作直接 EPERM（若 shim 同步目标位于 app 目录，必炸）。
- **解决方案**：
  1. 打包 `files` 白名单（示例，builder 语法；forge 用户对应 packageConfig）：
